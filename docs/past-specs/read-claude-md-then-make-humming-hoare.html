Plan: Issue #62 - GPT最新APIへの対応

Context

Issue #62の要望: GPT-5.5やGPT-5.4ファミリーなど、最後の修正以降にリリースされたより高性能・低コストなモデルへの対応。 現在のコードは gpt-5, gpt-5-mini, gpt-5-nano, gpt-4o までしかサポートしていない。

コスト比較（1M tokensあたり）:
新規追加モデル:
gpt-5.5: $5.00 input / $30.00 output
gpt-5.4: $2.50 input / $15.00 output
gpt-5.4-mini: $0.75 input / $4.50 output
gpt-5.4-nano: $0.20 input / $1.25 output

既存モデル（互換性維持）:
gpt-5: $1.25 input / $10.00 output
gpt-5-mini: $0.25 input / $2.00 output
gpt-5-nano: $0.05 input / $0.40 output

※ gpt-5系既存モデルはレガシーモデルとして位置づけられており、既存統合のために提供されています。
注意: requestTokens の大幅増加
gpt-5.4 の場合 requestTokens = 1,050,000 - 128,000 - 100 = 921,900 となり、 従来の gpt-5（271,900）の約3.4倍になる。
src/review.ts と src/review-comment.ts で requestTokens を入力サイズ上限として使用しているため、 1回のAPIリクエストに含まれるdiff量が大幅に増える可能性がある。
→ タイムアウト設定（デフォルト360秒）で十分か、APIコストの増大が許容範囲か確認すること。

モデル一覧（変更後）

GPT-4系（gpt-4o, gpt-4, gpt-4-32k, gpt-3.5-turbo 等）は全て削除する。既に5系しか使用していないため。

変更対象ファイルと内容

1. src/limits.ts

GPT-4系の全分岐を削除し、GPT-5系のみの個別列挙に書き換える。startsWith は使わない（gpt-5.4 と gpt-5.4-mini で maxTokens が異なるため区別が必要）。

削除対象:

  • model === 'gpt-4o' 分岐（knowledgeCutOff, maxTokens両方）
  • model === 'gpt-4-32k' 分岐
  • model === 'gpt-3.5-turbo-16k' 分岐
  • model === 'gpt-4' 分岐
  • コンストラクタのデフォルト引数 'gpt-3.5-turbo' → 'gpt-5.4-mini' に変更

変更後の分岐構造（knowledgeCutOff）:

if (model === 'gpt-5.5')                                     → '2025-12-01'
else if (model === 'gpt-5.4' || 'gpt-5.4-mini' || 'gpt-5.4-nano') → '2025-08-31'
else if (model === 'gpt-5' || 'gpt-5-mini' || 'gpt-5-nano')       → '2024-08-01'
else                                                               → '2024-08-01'  // フォールバック

変更後の分岐構造（maxTokens / responseTokens）:

if (model === 'gpt-5.5' || model === 'gpt-5.4')                    → maxTokens=1050000, responseTokens=128000
else if (model === 'gpt-5.4-mini' || model === 'gpt-5.4-nano')     → maxTokens=400000,  responseTokens=128000
else if (model === 'gpt-5' || 'gpt-5-mini' || 'gpt-5-nano')       → maxTokens=400000,  responseTokens=128000
else                                                               → maxTokens=400000,  responseTokens=128000  // フォールバック

2. src/openai-client.ts (line 152-168)

  • GPT-4系が存在しないため、isGpt5 分岐を削除し、常に max_completion_tokens を使用する
  • max_tokens 側の分岐（旧GPT-4系用）も削除

変更後:

// buildRequestBody 内
body.max_completion_tokens = this.options.maxTokens
// isGpt5 判定、max_tokens 分岐は削除

3. src/options.ts (line 36-37, 184)

  • デフォルトモデルを変更:
    • openaiLightModel: 'gpt-4o' → 'gpt-5.4-mini'
    • openaiHeavyModel: 'gpt-4o' → 'gpt-5.4'
  • OpenAIOptions クラスのデフォルト引数: 'gpt-3.5-turbo' → 'gpt-5.4-mini'

4. action.yml (line 155, 159)

  • デフォルト値を options.ts と同じく更新

5. __tests__/limits.test.ts

  • GPT-4系テスト（gpt-4o, gpt-4, 未知モデル）を削除
  • GPT-5.5, GPT-5.4, GPT-5.4-mini, GPT-5.4-nano のテストケースを追加

6. __tests__/openai-client.test.ts

  • GPT-4o のテストを削除
  • isGpt5 分岐削除に伴い、全モデルで max_completion_tokens を使用することの確認テストに変更
  • テスト対象モデルID: gpt-5, gpt-5.4, gpt-5.4-mini, gpt-5.4-nano, gpt-5.5

検証方法

  2. npm run build でビルド成功を確認
  3. dist/index.js が更新されていることを確認し、コミットに含める
  4. 既存のGPT-5モデルのテストが引き続きパスすることを確認（回帰なし）
